# RTX 3090 CUDA versus origin/main protocol

`scripts/benchmark_rtx3090_cuda.py` compares the PR's `cuda_streamed` FDTD
backend with the exact `origin/main` revision on a single RTX 3090. The baseline
is the pre-PR BeamZ JAX/XLA implementation on the same GPU; it does not import or
register `beamz_cuda`. This distinguishes the custom CUDA kernels from a CPU
comparison, which would measure a different processor rather than the PR change.

The default profile is a homogeneous `96 × 128 × 192` float32 3D Yee grid with
PEC faces and 200 timesteps. It intentionally excludes sources, monitors, and
CPML: this is the FDTD update throughput that the streamed kernels replace. Each
side receives three allocator/clock warmups followed by eleven independent
already-compiled executable samples. The first lowering and executable compilation
are recorded separately and never folded into runtime throughput.

Run from the checked-out PR branch after installing the optional CUDA wheel:

```console
python scripts/benchmark_rtx3090_cuda.py
```

The command creates a temporary detached `origin/main` worktree, runs both sides
in fresh processes with the same JAX CUDA installation, then removes that
worktree. It writes these ignored artifacts to `benchmarks/results/rtx3090/`:

- `rtx3090-cuda-comparison.json`: raw samples, provenance, percentile statistics,
  deterministic bootstrap median intervals, and derived GCUPS.
- `rtx3090-cuda-comparison.md`: a compact table suitable for a PR comment.
- `rtx3090-cuda-comparison.png`: median runtime (with 95% bootstrap error bars),
  GCUPS, and compilation-time charts.

The process exits non-zero when custom CUDA is slower than the `origin/main`
baseline, making a regression visible in automated hardware jobs. Pass explicit
`--shape`, `--timesteps`, and `--samples` values to establish another controlled
record; do not compare differently shaped records.

## Verified RTX 3090 result

The default profile was measured on 2026-08-12 at candidate revision
`7a673042ed352f060145318a69051ad986fcccc5`, against baseline revision
`8490470713ccc42bcf52065785feeb0bbefc58ae` from `origin/main`:

| Implementation | Median runtime | 95% bootstrap CI | Throughput |
| --- | ---: | ---: | ---: |
| `origin/main` JAX/XLA | 71.018 ms | 69.993–71.814 ms | 6.644 GCUPS |
| PR `cuda_streamed` | 49.015 ms | 48.593–49.855 ms | 9.627 GCUPS |

The custom CUDA implementation was **1.449× faster** (95% independent-bootstrap
CI 1.419–1.470×), reducing median runtime by 31.0% and increasing update
throughput by 44.9%. Its separately measured compilation step was 21.0× faster.
Compared with the preceding verified CUDA result, specializing uniform full-PEC
updates reduced CUDA median runtime by another 2.6%. These figures are specific
to the hardware, revisions, and default profile above; rerun the command to
reproduce them or to measure another controlled profile.

The matching opt-in pytest gate is deliberately disabled on ordinary machines:

```console
BEAMZ_RUN_RTX3090_BENCHMARK=1 pytest tests/hardware/test_rtx3090_cuda_benchmark.py
```

## Cumulative feature matrix

`scripts/benchmark_rtx3090_matrix.py` measures the same isolated revisions over
five cumulative feature profiles. Its default matrix uses a `64 × 96 × 128`
grid, 160 timesteps, three warmups, and eleven samples per implementation and
profile:

```console
python scripts/benchmark_rtx3090_matrix.py
```

At candidate revision `9e4b7aa`, against `origin/main` revision `8490470`, the
clean post-commit run produced:

| Workload | `origin/main` JAX | PR CUDA | Speedup (95% CI) | CUDA throughput |
| --- | ---: | ---: | ---: | ---: |
| Uniform PEC | 20.032 ms | 14.341 ms | 1.397× (1.366–1.415×) | 8.774 GCUPS |
| Heterogeneous PEC | 19.572 ms | 16.069 ms | 1.218× (1.201–1.239×) | 7.831 GCUPS |
| Heterogeneous CPML | 28.441 ms | 24.935 ms | 1.141× (1.124–1.159×) | 5.046 GCUPS |
| CPML + source | 32.038 ms | 27.412 ms | 1.169× (1.149–1.190×) | 4.590 GCUPS |
| CPML + source + DFT monitor | 35.417 ms | 32.271 ms | 1.097× (1.071–1.125×) | 3.899 GCUPS |

All intervals are deterministic independent-bootstrap 95% intervals for the
ratio of medians. The matrix creates ignored JSON, Markdown, and PNG artifacts
under `benchmarks/results/rtx3090/matrix/`.

## Follow-up experiments

Four proposed directions were evaluated on the same RTX 3090:

1. **Feature matrix — retained.** The matrix above prevents a fast uniform
   stencil from hiding regressions in heterogeneous materials, CPML, source
   injection, or DFT accumulation.
2. **CPML bulk kernel plus slab corrections — rejected.** Parity passed, but the
   twelve additional slab-kernel launches per timestep dominated the saved
   interior checks. Speedup versus main fell to 0.734× for heterogeneous CPML,
   0.764× with a source, and 0.772× with a source and monitor.
3. **Mixed-rank full-PEC material kernel — rejected.** Specializing scalar decay
   with dense source coefficients increased the heterogeneous-PEC CUDA median
   from 15.628 ms to 16.269 ms, about 4.1%. The generic broadcast-aware kernel
   remains faster on Ampere.
4. **Persistent source-free CPML graph — retained.** A dedicated typed FFI call
   now aliases fields and all twelve CPML recurrence buffers and captures the
   complete multi-step run in one CUDA graph. In a 21-sample same-binary A/B,
   the CUDA median fell from 25.416 ms to 24.726 ms: a 1.028× speedup with 95%
   bootstrap CI 1.020–1.043×. End-to-end speedup against main rose from 1.127×
   to 1.161× in that controlled A/B.

The source and DFT profiles remain the limiting cases because their per-step JAX
work prevents whole-run graph capture. The next experiment should move the
common packed source slab into the CUDA phase call, then add a CUDA DFT plane
accumulator or graph source-free intervals between scheduled observations.
